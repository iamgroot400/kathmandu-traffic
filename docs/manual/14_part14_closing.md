# Part XIV — Closing

## Chapter 47: What We Would Do Differently

A manual that only celebrates what went well would be teaching a false lesson. Several
of this project's own choices, recorded honestly in its decision log and assumption
register, are limitations this project would address first, given more time or a
second attempt:

### Validation should have come earlier, not after the headline claims were set

This project's GEH validation (Part IX) was conducted after its core result (the
combined-lever finding) had already become the project's working headline claim. Had
validation come first, the known 2-of-6 pass rate — and the specific, Koteshwor-level
single-seed reversal of the adaptive-signal finding (Chapter 36) — would have shaped
how confidently the headline claim was stated from the very beginning, rather than
being added afterward as a caveat to an already-settled conclusion.

### The demand model's single biggest untested assumption deserves more direct attention

Every result in this project ultimately rests on **assumption A1**: that junction
density is a reasonable proxy for real trip-generating activity. This project tested
one specific refinement of that proxy (lane-weighted junction mass, Chapter 9) and
found it did not help — a genuine, honest negative result — but it never tested a
fundamentally different proxy altogether (land-use data, if it ever becomes available
for Kathmandu Valley, or a small, targeted household survey covering even a handful
of zones) that might diagnose whether the *entire family* of junction-density-based
proxies is the real limiting factor behind this project's validation gap, rather than
just this one specific weighting scheme within that family.

### The decentralized-attraction confound (Chapter 23) should have been resolved, not just named

This project correctly identified that its decentralized-attraction result is
confounded with a pure demand-reduction effect, and correctly declined to claim more
than its evidence supports. But the fix — a volume-matched control, applying the same
total demand cut uniformly rather than concentrated at the core — is simple to specify
and was never actually run. This is the single most "shovel-ready" piece of unfinished
work this project leaves behind.

### More seeds, specifically where the capacity-sweep reversal happens

Chapter 38's capacity-sensitivity sweep found a reversal in the individual levers'
benefit somewhere between 1,600 and 2,000 vehicles per hour per lane, but at only 5
seeds per capacity level, this project's own confidence intervals are wide enough,
particularly at 1,600, that "not significant" there cannot be read as "no effect" —
only as "not detected at this sample size." A follow-up extending specifically this
range to the project's full, 15-seed standard would sharpen exactly where and how
sharply this reversal occurs — work that was, in fact, already underway (and
deliberately paused mid-run, to be resumed later) at the time this manual was written.

## Chapter 48: Open Questions

This project leaves behind a specific, named list of open questions, each already
flagged somewhere in its own records rather than newly invented for this closing
chapter:

- **Does day-to-day route equilibrium genuinely not exist on this network, or did the
  solver simply need better tuning?** (Chapter 16) — not determined.
- **Why did adding cordon (external boundary) demand make one specific landmark's
  face-validity worse, with no map-boundary explanation available?** (Chapter 24,
  the unexplained Chabahil failure) — not resolved.
- **Would a genuinely different demand-activity proxy — not just a different weighting
  of the same junction-density idea — improve this project's validation gap?**
  (Chapter 9, Chapter 47) — not tested.
- **Is the decentralized-attraction result a genuine redistribution effect, a pure
  demand-reduction effect, or some mixture of the two?** (Chapter 23) — the
  volume-matched control that would answer this was never run.
- **Exactly where, between 1,600 and 2,000 vehicles per hour per lane, does the
  individual-lever reversal (Chapter 38) actually occur, and how sharp is the
  transition?** — a follow-up with more seeds in this specific range is underway.
- **Would a congestion-pricing scheme with genuinely automated, enforcement-free
  detection (rather than this project's assumed, implicit human-enforced model)
  avoid the deployability concerns raised in Chapter 41?** — an open design question
  this project's own evidence does not resolve either way, since it was never
  specifically modeled.

This manual, like the research it documents, is not a finished, closed account — it is
a faithful record of what was actually done, what was actually found, and what
honestly remains unknown, written so that the next person to pick this project up —
whether that is a future version of this same team, or someone new entirely — can
continue from exactly where it stands, rather than having to rediscover any of this
from scratch.
